如何解決 `400: redirect_uri_mismatch` 錯誤並成功配置 Google OAuth 2.0 與 n8n

在使用 n8n 自架 Docker 環境並配置 Google OAuth 2.0 認證時，你可能會遇到 400: redirect_uri_mismatch 錯誤。這個錯誤通常是由於 Google OAuth 配置中的回調 URI 與實際使用的 URI 不匹配所導致的。 本文將逐步引導你解決這個問題，並讓你能夠順利將 Google 服務與 n8n 進行集成。 什麼是 redirect_uri_mismatch 錯誤？ redirect_uri_mismatch 是 OAuth 2.0 流程中的一種常見錯誤。當 Google 在認證過程中發現傳入的回調 URI 與註冊的回調 URI 不匹配時，就會顯示這個錯誤。這樣的情況通常出現於以下幾種情況： 回調 URI 在 Google Cloud Console 中的設置與 n8n 中使用的 URI 不一致。 使用 Docker 容器運行 n8n 時，localhost 和容器的網絡配置未正確處理。 確認 n8n 中的回調 URI 首先，確認 n8n 中使用的回調 URI。根據 n8n 文檔，默認的回調 URI 是： http://localhost:5678/rest/oauth2-credential/callback 如果你在本地運行 n8n，請確保這個 URI 在 n8n 配置中正確設置。如果你是在 Docker 中運行 n8n，則可能需要根據 Docker 的網絡配置來調整 URI。 ...
